# Primitive DB - простая реляционная база данных

## Описание проекта
Primitive DB - это консольное приложение на Python, имитирующее работу с реляционной базой данных. Проект поддерживает создание таблиц, выполнение CRUD-операций и обеспечивает персистентность данных через JSON-файлы. Приложение разработано с использованием современных инструментов Python и следует принципам чистого кода.

## Основные возможности
Создание и удаление таблиц с поддержкой типов данных: int, str, bool
Автоматическое добавление первичного ключа ID для каждой таблицы
Полный набор CRUD-операций: вставка, выборка, обновление, удаление записей
Фильтрация данных с помощью условий WHERE
Форматированный вывод таблиц с помощью библиотеки PrettyTable
Хранение данных в JSON-файлах
Обработка ошибок через декораторы
Кэширование результатов запросов
Подтверждение опасных операций

## Установка и запуск
Предварительные требования
Python 3.12 или выше

Менеджер пакетов Poetry

Установка
Клонируйте репозиторий проекта

Установите Poetry, если он еще не установлен:

pip install poetry
Перейдите в директорию проекта и установите зависимости:

make install
Сборка и установка пакета
Для сборки пакета выполните:

make build
Для установки пакета в систему:

make package-install
Запуск
После установки пакета приложение можно запустить командой:


make project
Или из директории проекта:

poetry run project


## Команды
Работа с таблицами
create_table <имя_таблицы> <столбец1:тип> <столбец2:тип> ... - создать таблицу
drop_table <имя_таблицы> - удалить таблицу (с подтверждением)
list_tables - показать список всех таблиц
info <имя_таблицы> - вывести информацию о таблице

CRUD-операции
insert into <имя_таблицы> values (<значение1>, <значение2>, ...) - создать запись
select from <имя_таблицы> - прочитать все записи
select from <имя_таблицы> where <столбец>=<значение> - прочитать записи по условию
update <имя_таблицы> set <столбец>=<новое_значение> where <столбец_условия>=<значение_условия> - обновить запись
delete from <имя_таблицы> where <столбец>=<значение> - удалить запись (с подтверждением)

Общие команды
help - показать справку по командам
exit - выйти из программы

Поддерживаемые типы данных
int - целые числа
str - строки (в двойных или одинарных кавычках)
bool - булевы значения (true/false)

## Примеры использования

Создание таблицы
create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool

Добавление записей
insert into users values ("Иван", 25, true)
Запись с ID=1 успешно добавлена в таблицу "users"

Выборка данных
select from users where age=25
Выведет таблицу с пользователями возрастом 25 лет

Обновление данных
update users set age=26 where name="Иван"
Обновлено 1 записей в таблице "users"

Удаление данных
delete from users where ID=1
Вы уверены, что хотите выполнить 'удаление записи'? [y/n]: y
Удалено 1 записей из таблицы "users"

Получение информации о таблице
info users
Таблица: users
Столбцы: ID:int, name:str, age:int, is_active:bool
Количество записей: 3

## Особенности реализации
### Декораторы
Проект использует декораторы для расширения функциональности:

@handle_db_errors - централизованная обработка ошибок базы данных
@confirm_action - запрос подтверждения для опасных операций
@log_time - замер времени выполнения операций

### Кэширование
Реализовано кэширование результатов запросов SELECT через механизм замыканий. Функция create_cacher() создает кэшер, который хранит результаты запросов и возвращает их при повторных одинаковых запросах, что ускоряет работу с часто запрашиваемыми данными.

### Валидация данных
Все входящие данные проходят строгую валидацию:
Проверка соответствия типов данных
Валидация формата определений столбцов
Проверка уникальности имен столбцов

### Обработка ошибок
Централизованная обработка ошибок через декоратор @handle_db_errors перехватывает:
FileNotFoundError - отсутствие файлов данных
KeyError - обращение к несуществующим таблицам или столбцам
ValueError - ошибки валидации типов данных

## Примечания
Столбец ID создается автоматически для каждой таблицы и не может быть задан пользователем
Все поля таблицы являются обязательными
Для строковых значений требуются кавычки (двойные или одинарные)
Числовые значения вводятся без кавычек
Булевы значения принимаются как true/false, 1/0, yes/no
При удалении таблиц или записей запрашивается подтверждение
Результаты запросов SELECT кэшируются для повышения производительности
